# Изображения в Google Документе

Использовать при оформлении цепочки и запросах «где иллюстрация к посту — вставь саму картинку над ссылкой».

## Прочитать место назначения

Получить актуальную ревизию документа и затрагиваемые вкладки через get_document. Определить tabId, индекс абзаца ссылки и URL из textStyle.link.url. Подпись «Иллюстрация к посту» может скрывать адрес: не искать только видимые URL.

Ответ коннектора может содержать body непосредственно во вкладке или documentTab.body. Учитывать актуальную структуру и дочерние вкладки.

Для каждой ссылки сохранить соответствие: день и пост, tabId, индекс, URL и ID изображения. Если непосредственно над ссылкой уже стоит нужная картинка, не создавать дубль.

## Получить файлы и размеры

- Прочитать метаданные уникальных Drive-файлов и подтвердить MIME изображения.
- Получить файл через fetch с download_raw_file=true и include_base64=false. Использовать возвращённый file_uri или материализованный путь.
- При необходимости скачать файл по возвращённому download_url в рабочую папку и прочитать ширину и высоту через Pillow.
- Не сохранять временные подписанные URL в скилле или постоянном реестре шаблонов.
- Повторяющийся коллаж загружать один раз, но вставлять отдельный нативный объект у каждой соответствующей ссылки.

Drive-адрес /file/d/.../view является страницей просмотра. Для insertInlineImage нужен прямой доступный URL самой картинки: например, актуальный download_url из fetch. Также можно передать локальный файл через поддерживаемый коннектором image_uris; форму аргумента проверить по актуальной схеме инструмента.

## Размеры без искажения

Определить доступную ширину по размеру страницы и полям. Обе стороны масштабировать одним коэффициентом:

scale = min(maxWidth / originalWidth, maxHeight / originalHeight)

Для A4 с полями около 72 pt удобная начальная рамка предпросмотра — до 420 pt по ширине и до 360 pt по высоте. Это ориентир: учитывать сам документ и запрос пользователя.

Не растягивать, не вырезать края и не изменять оригиналы ради вставки.

## Вставить над ссылкой

Составить согласованную пачку запросов. Внутри каждой вкладки обрабатывать позиции в убывающем порядке. Индексы Google Docs — UTF-16: в JavaScript использовать .length, а не число Unicode-символов.

Для ссылки с исходным индексом p:

1. insertText с переводом строки в p создаёт отдельный абзац перед ссылкой.
2. insertInlineImage в тот же p помещает картинку в этот абзац. Указать tabId, прямой URI и обе стороны objectSize в PT.
3. Абзацу изображения задать NORMAL_TEXT, небольшой отступ после и keepWithNext=true, чтобы картинка оставалась со ссылкой.
4. Сохранить стиль и адрес ссылки. Можно применить keepWithNext к её абзацу, чтобы она оставалась с заголовком самого поста.

В этой паре вставок исходный текст смещается на две позиции: изображение и перевод строки. Обратный порядок сохраняет исходные индексы более ранних ссылок.

Передавать requiredRevisionId из свежего чтения. При конфликте прочитать затронутые места и пересобрать план. При неопределённом исходе сначала проверить уже вставленные объекты, чтобы не создать дубли.

Для добавления картинок не заменять весь документ, не удалять ссылки и не менять посты.

## Проверить результат

Одним чтением после пачки подтвердить:

- Число новых inlineObjectElement соответствует числу мест для вставки.
- За каждым новым абзацем с изображением стоит нужная ссылка.
- У каждого объекта есть embeddedObject.imageProperties и корректный размер.
- Пропорции совпадают с исходными файлами.
- Исходный текст и адреса ссылок сохранены.

Экспортировать актуальный документ в PDF для визуальной проверки. У files.export есть лимит 10 МБ; для большого PDF использовать доступный потоковый fetch с include_base64=false и raw_export_mime_type=application/pdf.

Отрендерить PDF и посмотреть все страницы с изображениями: нет пустых кадров, обрезки, отрыва ссылки от картинки. Если на обзорном листе изображение кажется пустым или нечитаемым, сначала открыть саму страницу в полном размере, прежде чем менять документ.
